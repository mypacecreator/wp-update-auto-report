# WP Update Auto Report

WordPress コア・プラグイン・テーマのアップデート差分を記録し、クライアント提出用の月次作業報告書（Markdown）を管理画面から生成するプラグインです。

---

## 必要環境

### 基本機能（固定フォーマットレポート）

- WordPress 6.0 以上
- PHP 8.0 以上

### AI詳細レポート生成（オプション）

- WordPress 7.0 以上
- Connectors API の設定（管理画面 ＞ 設定 ＞ コネクタ）
  - 対応プロバイダー: OpenAI / Anthropic / Google など

---

## インストール

### ZIP インストール（推奨）

1. [Releases](https://github.com/mypacecreator/wp-update-auto-report/releases) から最新の ZIP をダウンロード
2. WordPress 管理画面 ＞ **プラグイン ＞ 新規追加 ＞ プラグインのアップロード** から ZIP をインストール
3. プラグインを有効化

### Git クローン

```bash
cd wp-content/plugins/
git clone https://github.com/mypacecreator/wp-update-auto-report.git
```

有効化は管理画面 ＞ **プラグイン** から行ってください。

---

## 使い方

### 基本の流れ（3ステップ）

**STEP 1 — アップデート前**

1. 管理画面 ＞ **ツール ＞ WP レポート生成** を開く
2. **「現在の状態をスナップショット」** ボタンをクリック
3. 「スナップショット取得済み（日時）」と表示されたことを確認

**STEP 2 — アップデート後**

4. 通常のアップデート作業（コア・プラグイン・テーマ）を実施
5. フロントエンドやフォームを目視で確認
6. 再度 **ツール ＞ WP レポート生成** を開く
7. 「差分プレビュー」で更新内容を確認
8. レポートを生成（スナップショットは保持されるため、どちらも何度でも生成可能）
   - **「レポートを生成する」** — 固定フォーマットの簡易レポート（即座に生成）
   - **「AI詳細レポートを生成」** — リリースノート付き詳細レポート（WordPress 7.0以上で表示）
9. 表示された Markdown テキストをコピーまたはダウンロード

**STEP 3 — 作業完了後**

10. **「スナップショットをリセット」** ボタンをクリックしてスナップショットを削除
    - リセットしないと、次回のスナップショット取得まで古い差分が残り続けます
    - リセット後はページが自動でリロードされ、STEP 1 の状態に戻ります

### コピー・ダウンロード

| ボタン | 動作 |
|--------|------|
| **リッチテキストでコピー** | Word や Google Docs にそのまま貼り付け可能な形式でコピー |
| **Markdown でダウンロード** | `report_YYYYMMDD.md` ファイルとしてローカルに保存 |

> **注意:** 「リッチテキストでコピー」は Clipboard API（HTTPS 環境）が必要です。HTTP 環境ではテキストとしてコピーされます。

## AI詳細レポート生成機能

WordPress 7.0 で導入された **Connectors API** を使い、各アップデートのリリースノートを自動取得してAIが詳細レポートを生成します。

### 前提条件

1. **WordPress 7.0 以上**
2. **Connectors API の設定**
   - 管理画面 ＞ **設定 ＞ コネクタ** でAIプロバイダーを設定
   - 対応プロバイダー: OpenAI / Anthropic / Google など

### 仕組み

1. **リリースノート自動取得**
   - WordPress.org API からコア・プラグイン・テーマのリリースノートを取得
   - 24時間キャッシュで高速化（Transient使用）
   - 非公開プラグインや取得失敗時は「（取得できませんでした）」として処理

2. **AIレポート生成**
   - 差分データ + リリースノートをプロンプトテンプレートに展開
   - Connectors API（`wp_ai_client_prompt`）で非技術者向けレポートを生成
   - セキュリティ・安定性・機能面の改善を簡潔に説明

### 使用モデル

デフォルトでは **Claude Haiku 4.5** を使用します。

生成されたレポートの末尾に「**使用モデル:**」として実際に使用されたモデル名が表示されます。

モデルは管理画面から変更できます。**ツール ＞ WP レポート生成** を開き、ページ下部の「設定 — AI モデル選択」でドロップダウンからモデルを選択して「設定を保存」をクリックしてください。

| モデル | 特徴 |
|--------|------|
| Claude Haiku 4.5 | 高速・低コスト（デフォルト） |
| Claude Sonnet 4.5 | バランス型・動作確認済み |
| Claude Sonnet 4.6 | バランス型（環境によりタイムアウトの可能性あり） |
| Claude Opus 4.8 | 高精度 |

デフォルトモデルや選択肢の追加・変更は、`wp-update-auto-report.php` 内の定数 `WUAR_AI_MODELS`（モデル ID と表示名の一覧）と `WUAR_AI_MODEL_DEFAULT` を編集してください。

### プロンプトテンプレートのカスタマイズ

運用者は `templates/prompt-ai-report.md` を編集してAIへの指示内容をカスタマイズできます。

**編集例:**

```bash
cd wp-content/plugins/wp-update-auto-report/
nano templates/prompt-ai-report.md
```

**テンプレート内のプレースホルダー:**

- `{diff_and_notes}` — 差分データとリリースノートが自動展開されます

ファイルが存在しない場合はデフォルトテンプレートが使用されます。

### 注意事項

- **プラグインslug推測の制約**: プラグイン名からslugを推測するため、一部のプラグインではリリースノート取得に失敗する場合があります
- **処理時間**: AIレポート生成には数秒〜数十秒かかる場合があります
- **費用**: Connectors APIの利用料金はプロバイダーの規約に従います

## マルチサイト（ネットワーク）対応

WordPress マルチサイト環境では、プラグイン・テーマのアップデート権限を持つのはネットワークの特権管理者（Super Admin）に限られます。これに合わせ、本プラグインのレポート機能もマルチサイト環境ではネットワーク管理者専用の機能になります。

### 個別サイトの「ツール」メニューは表示されません

マルチサイト環境では、各ブログの管理画面 ＞ **ツール ＞ WP レポート生成** は表示・利用できません（メニュー自体が非表示になります）。レポート生成はネットワーク管理画面からのみ行えます。

### 使い方

1. ネットワーク管理画面（`wp-admin/network/`）＞ **設定 ＞ WP レポート生成** を開く
2. STEP 1〜3 の流れは単一サイト版と同様です
3. レポートは**ネットワーク全体で1本のリスト**として生成されます（個別サイトごとの内訳はありません）

### 対象範囲

プラグイン・テーマの実体ファイルはマルチサイトのネットワーク全体で共有されており（サイトごとに異なるのは「有効化しているか」だけ）、本プラグインはネットワーク管理画面の「プラグイン」「テーマ」一覧と同じ対象範囲でレポートします。

- **プラグイン**: ネットワークにインストールされている**全プラグイン**が対象です。特定のサイトで有効化されているかどうかは問いません（無効化されているプラグインの更新も対象になります）
- **テーマ**: 有効・無効を問わず、インストール済みの全テーマが対象になります（単一サイト版と同様）
- **コア**: WordPress 本体のバージョンが対象になります

### AI詳細レポート生成

ネットワーク管理画面にも、単一サイト版と同様のAIモデル選択欄（「設定 ＞ WP レポート生成」ページ下部）があります。AI詳細レポートを利用するには、事前に Connectors API（設定 ＞ コネクタ）でAIプロバイダーを設定してください。

### 単一サイト環境への影響

単一サイト（非マルチサイト）環境には一切影響がなく、従来通りの画面・操作方法がそのまま使えます。

## アップデート時の注意事項（マルチサイト環境）

マルチサイト対応の追加に伴い、マルチサイト環境での挙動が変更されました。

- **変更前**: 各ブログの「ツール ＞ WP レポート生成」から、`manage_options` を持つ全ユーザー（各サイトの管理者を含む）が個別にレポート生成できました。
- **変更後**: マルチサイト環境では個別サイトのメニュー・機能が完全に無効化され、ネットワークの特権管理者のみがネットワーク管理画面からレポート生成できます。

この変更の影響が及ぶのはマルチサイト環境のみで、単一サイト環境の挙動・画面は変更されません。

> **注意:** アップデート前に個別サイトでスナップショットを取得済み（STEP 1 実施済み・STEP 2 未実施）だった場合、データ自体は削除されませんが、アップデート後は個別サイトの画面が無くなるため確認・利用ができなくなります。該当作業が進行中の場合は、アップデート適用前にレポート生成またはスナップショットのリセットを済ませておくことを推奨します。本バージョンでは、この移行に関する自動対応・データの後方互換対応は行っていません。

## よくある質問

**Q. スナップショットを取り忘れてアップデートしてしまった**  
A. スナップショット未取得の場合、「レポートを生成する」ボタンは無効化されレポートを生成できません。アップデート内容を手動で記録し、次回からは必ず STEP 1 を先に行ってください。

**Q. テーマのアップデートも記録されますか？**  
A. はい。インストール済みの全テーマ（有効・無効問わず）のバージョンを記録・比較します。

**Q. スナップショットのデータはどこに保存されますか？**  
A. WordPress の `wp_options` テーブル（オプション名: `wuar_version_snapshot`）に保存されます。

**Q. AIによる詳細レポートは生成できますか？**
A. はい。WordPress 7.0 以上の環境で Connectors API を設定することで、「AI詳細レポートを生成」ボタンが表示されます。このボタンをクリックすると、各アップデートのリリースノートを自動取得し、非技術者向けに分かりやすく説明した詳細レポートが生成されます。

**Q. WordPress 6.x でもこのプラグインは使えますか？**
A. はい。WordPress 6.0 以上であれば基本機能（固定フォーマットレポート）は利用可能です。ただし、AI詳細レポート生成機能は WordPress 7.0 以上でのみ利用できます。WordPress 6.x では「AI詳細レポートを生成」ボタンは表示されません。

**Q. AIレポート生成に失敗した場合はどうなりますか？**
A. エラーメッセージが表示され、レポートは生成されません。この場合、以下を確認してください：
- Connectors API（設定 ＞ コネクタ）が正しく設定されているか
- APIキーの有効期限や利用制限に達していないか
- ネットワーク接続が正常か

失敗時はスナップショットはリセットされないため、再度「AI詳細レポートを生成」または「レポートを生成する」を試すことができます。
